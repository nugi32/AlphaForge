# Engineering notes

Append-only log of decisions, gotchas, and open questions. Newest at the bottom.
Format: `D-xxx` decision, `G-xxx` gotcha, `Q-xxx` open question.

- D-001 Language: every file in this project (code, comments, docs, tests, config) is written in English.
- D-002 The package keeps the name `edge_research` so the old loader works UNCHANGED (loader.py, economic_calendar.py, memory.py, run_dir.py, checkpoint/*, known_at/tagging.py are verbatim copies from the old project; do not edit them).
- D-003 Label validity is evaluated per exit family (each family uses its own maximum hold), not with one global maximum hold. Revisit if cross-family comparisons need a common row set.
- D-004 Bar-boundary barriers (family B): levels are measured from the entry fill price (long: ask entry, short: bid entry); the test uses the CLOSED bar close (bid) for both directions; exit fills at the next bar open. The engine (M2b) must reuse the exact same function.
- D-005 Swap is vectorized through a cumulative weighted rollover count; it must equal the old `swap_nights()` loop (tested).
- D-006 Commission is converted to price units as `2 * commission_per_lot_per_side / contract_size`; this assumes the deposit currency equals the quote currency (true for XAUUSD and EURUSD on a USD account, false for e.g. USDJPY). Revisit for non-USD-quoted symbols.
- D-007 Synthetic generator: the planted edge is defined on an exogenous volatility process (sigma), not on indicators, so planting does not create circularity with indicator values.
- Q-001 Feature cluster representative tie-break: lowest MQL5 complexity, then lowest NaN fraction, then name. Spec also mentions "most stable distribution"; not implemented yet.
- D-008 Label validity treats the gap between the signal bar i and the entry bar e=i+1 as part of the window: a signal on the last bar before a weekend gap (> max_gap_hours) is invalid, because the fill would happen on a stale signal.
- G-001 pandas 3 returns read-only numpy views from `.to_numpy()`; always `np.array(..., copy=True)` before in-place edits.
- G-002 `edge_research.features.registry.MA_PREFIX` also matches exporter columns like `ma_5_sma`; verify on the real CSV that column names follow `ma_<n>_<type>` (not checked against a real export yet: no real data was available in session 1).
- D-009 Stage fingerprints = data hash + hash of the stage's config sections + stage code version (`pipeline.STAGE_VERSIONS`). Bump the version string of a stage whenever its code changes behaviour.
- D-010 The old `checkpoint/` package (RunSession, RunLock, store) is copied but NOT yet wired in; `pipeline.py` uses a simple manifest-based skip. Wire the old session/lock in at M7 (null-test replicates need per-replicate checkpoints).
- D-011 Feature clustering uses average linkage on 1-|Spearman| (scipy), cut at 1 - threshold; `time` features are exempt and always kept.
- D-012 Engine (`mt5_backtest/engine.py`) reuses `labels.builder._Market` and `barrier_exit_bars`; it contains no cost or barrier maths of its own. The test `tests/test_engine_vs_labels.py` checks net_R and hold against the label table for every configured family and both directions.
- D-013 Engine position rules: one position at a time; a signal whose entry bar is before `busy_until` is skipped. `reenter_on_exit_bar=false` (default) makes `busy_until = exit_bar + 1`, true makes it `exit_bar`. Invalid-window signals (gap, non-finite, past the end of data) are skipped and do NOT block later signals.
- D-014 A long and a short signal on the same bar are both dropped (`engine.conflict_policy: skip`); counted in `stats["conflict_skipped"]`.
- D-015 `exit_reason` is not reported: for family B a barrier hit on the last horizon bar and a time exit land on the same exit bar, so the reason is ambiguous. Add it only if a later stage needs it.
- Q-002 Engine takes boolean signals only; compounding, position sizing and equity curves are out of scope until M4+ (everything is in R units).
- D-016 Stage 3 uses TRAIN rows only (slice starts at max(train.start, first_valid_row)); a test destroys validation and holdout rows and checks the output is identical. Cluster-robust SE uses calendar weeks (CR1 small-sample factor); consistency uses years, or quarters when the train segment has fewer than 3 usable years.
- D-017 Hits are judged on the GROSS lift over the baseline, not on net R. Reason (measured): on null data, cost in R varies with hour (spread x2 at 23-00h) and with volatility regime, so net-lift hits appeared on `hour`, `session`, `atr_ratio` with no price information at all. Net mean, cost and net lift are still reported for every cell. Two extra safeguards: `t_min: auto` is one-sided Bonferroni over the tested cells (fixed 4.0 gave 2 false GO in 8 null seeds), and a hit also needs the cell's own gross mean to have t >= 2 (otherwise the mirror side of a planted long edge, which is only "less bad" than an edge-contaminated baseline, produced fake short hits).
- G-003 Sample-path trend of a random walk shows up as a nonzero baseline gross R (long and short mirror each other). The baseline flag in Stage 3 uses cluster t of gross >= 3; lift over the baseline removes this drift from the hit rule.
- Q-003 OPEN, needs the project owner's decision: the spec says "stop on NO_GO". On synthetic data the default planted edge (a conjunction: drop in the last 3 bars AND hours 7-11, about 0.5 R on the trigger bars only) is NOT visible in any single-feature bin at 3 years of train (lift about 0.07 R, t about 1.4), so Stage 3 says NO_GO although an edge exists. Config `eda.stop_on_no_go` is therefore false by default: the verdict is recorded and reported loudly but the run continues. Set it to true to follow the spec literally. Possible improvement: add a pairwise (feature x feature) view to the go/no-go.
- D-018 Decile plots (PNG) are not produced (spec: "if available"); the CSV has everything needed.
- D-019 Atom thresholds are rounded to 6 significant digits BEFORE masks are built, so the stored number is the rule and Python == MQL5 parity does not depend on float noise. The feature table is float32; comparisons use float64 of the stored values. MQL5 computes features in double, so expect rare boundary differences; the M10 parity tolerance must account for this.
- D-020 NaN rows are False for BOTH sides of a numeric pair; the derived `>` atom is `valid[feature] & ~mask(<=)` (exact complement within finite rows). Event flags get only `== 1`; categorical features (kind `time` or <= 10 train levels) get one `==` atom per level. Support is measured on all train rows (NaN rows count as False) and the filter is applied to the pair, so both sides stay within [1%, 99%].
- D-021 Atom family = Stage 1 correlation cluster (`cluster{N}`); exempt time features are their own family. `compatible()` allows two atoms of one feature only as an interval (`> lo` with `<= hi`, lo < hi); two levels of one categorical feature are never combined. Note: the kept feature list already holds one representative per cluster, so the family rule matters only if more than one member per cluster is ever kept.
- D-022 Row masks are materialised on ALL rows (train, validation, holdout) with train-only thresholds; `apply_atoms` re-materialises frozen atoms on any other table (used by validation later). Quantized 8-bit bins (255 = NaN) satisfy `x <= cut[k]  <=>  bin <= k` (tested incl. values exactly on a cut).
- Q-004 RESOLVED in M4b as D-023 (kept for history): the spec's pair statistics use `A^T diag(y) A` with float labels that contain NaN (windows leaving the data or crossing gaps). M4b must decide how NaN labels enter the products (proposal: zero the row in both A and y via a per-label valid mask, and compute row counts per label, not once globally).
- D-023 (resolves Q-004) NaN labels in pair statistics: each screening label has a validity mask v (finite outcome). Pair counts are `A^T diag(v) A` and sums `A^T diag(y0) A` with y0 = y where v else 0, so a row without an outcome is zero on BOTH sides. Counts are therefore per label (labels with identical masks share one product). `~B` is the LOGICAL complement (rows where the atom is False, including NaN-feature rows); the cells A&~B and ~A&B are marginal minus pair cell, restricted to rows valid for that label. Tested against brute force with NaN labels, chunk sizes that do not divide folds, and two float dtypes.
- D-024 Coarse screen (`discovery/pairs.py`): unit of output is (pair, direction). Filters per label: valid rows >= `min_rows_screen`; coarse t = mean * sqrt(n / hold) / sd_global >= `t_screen` (hold = max hold of the family, sd over valid train rows); >= `min_pos_folds` of `n_folds` contiguous time folds with >= `min_rows_fold` rows and a positive sum; lift over BOTH parents > 0, where lift_A = mean(A&B) - mean(A&~B) and lift_B likewise, and the screen uses min(lift_A, lift_B) (an empty remainder gives NaN, which fails). A (pair, direction) survives if it passes all filters on >= `min_labels_pass` (default 2 of 3) screening labels of that direction. Target is NET R by default (`discovery.target`), because rules must pay their costs; cost-in-R varies by hour and volatility (see D-017), so inspect gross vs net on survivors in M5. Survivors for the other direction have NaN in this direction's per-label columns. Pairs surviving in BOTH directions are flagged in summary.md (spec 10.6).
- D-025 Pair engine layout: atom columns are processed in blocks of `tile`; loop over block pairs (upper triangle, global index a < b); row chunks never cross a fold boundary; products in `matmul_dtype` (float32 default; counts are exact below 2^24) and accumulated in float64. Memory per tile = tile^2 x folds x (count groups + labels) float64. No combination mask is ever stored. Episodes are NOT used in the coarse screen (hold deflation instead); `discovery/episodes.py` is used for the exact statistics in M5. The optional extra weekly cluster of spec 10.4 is not implemented yet.
- D-026 Stage `05_discovery`: reads atoms (`04_atoms`) and labels (`02_labels`), TRAIN rows only (`aset.train`), writes `survivors_pairs.parquet`, `screen_info.json`, `summary.md`. Fingerprint sections: discovery, atoms, features, labels, costs, data. A test destroys all label rows after the train segment and checks identical survivors.

- Q-005 OPEN, needs a decision before M5: ordinal time features (`hour`, day of week) only get one `==` atom per level (D-020), so a RANGE of hours cannot be expressed in a pair. Measured: the DEFAULT `PlantedEdge()` (drop in the last 3 bars AND hours 7-11, about 0.5 R on trigger bars) gave 0 survivors at 30k, 60k and 100k bars with the default screen, and only noise survivors (115 long / 75 short, none containing the planted structure) with filters relaxed to min_rows 100, t 1.0, 3 of 5 folds, 1 label. - D-027 Lift clusters are fixed TIME BLOCKS, not episodes of the parent (`episodes.lift_stats(..., block=B)`, B = `candidates.lift_block_mult` x hold bars, default 5). Measured on the strong planted edge: the parent `session == 1` (2946 train rows) is 491 episodes for hold <= 12 but ONE episode at hold 24; any parent whose support exceeds roughly 1/hold chains the whole train into one episode (`rsi_14 > 38.98` has 90% support), and a single cluster has no SE, so the lift filter would reject every child of a dense parent on the long-hold families. Blocks keep rows closer than `g` bars (shared price path) in one cluster and give about n_train / B clusters for any parent. Blocks are anchored at the first train row; dependence across a block boundary is ignored (slightly anti-conservative; the factor 5 keeps it small). The rule's own statistics (mean, t, effective n) still use EPISODES of the trigger rows as in spec 10.4. `lift_stats(block=None)` keeps the episode mode for sparse parents.
- D-028 Candidate qualification (`discovery/candidates.py`): ALL 24 label families of the survivor's direction (6 T + 18 B) are evaluated, not only the 3 screening labels; target = `discovery.target` (net). A family PASSES when episodes >= `min_episodes_train` (episode gap = hold of that family), cluster t >= `t_exact` (2.5) and lift t >= `lift_t_min` (1.5) against BOTH parents; a candidate qualifies when >= `min_families_pass` (2) families pass. This is only a partial F3 (the spec wants >= 3 of 5 NEIGHBOURING exits; that belongs with M6). Lift is computed only for families that already pass episodes and t, so `lift_*` is NaN for the others in `candidate_families.parquet`. `best_family` is the max-t passing family: it is a SELECTED number (selection over 24 families); M6 must choose exits by plateau, not by this column. Rank score = MEDIAN t over ALL 24 families of the direction (non-finite t counts as -inf), so breadth counts: a first version used the mean t over the passing families only, and on the 40k-bar run the planted rule `ret_3_atr <= -1.44 & session == 1` (passes 23 of 24 families) ranked 12th behind rules that pass only 2 families.
- D-029 Dedup = greedy leader clustering in rank order on the Jaccard overlap of TRIGGER ROWS (train, A & B), default threshold 0.6 (the spec's `dedup_jaccard`; the spec talks about episode sets, row sets are used here because they need no extra pass; the checkpoint suggested 0.8 as an example). A candidate joins the BEST-RANKED representative with J >= threshold, else it becomes a representative. This is not single-linkage: members resemble their representative, not necessarily each other. Long and short candidates are never merged. Representative = best rank (spec: simplest first, then plateau score; all depth-2 rules have 2 atoms and there is no plateau score before M5b). The reported cluster count is an upper bound on independent ideas: two representatives below 0.6 overlap can still be one idea. The correlation-of-P&L criterion (0.7) is not implemented.

- D-031 Stage `07_filters` (M5b, `discovery/filters.py`): filters run on the BEST family of each candidate (the family whose number was selected), then the surviving candidates are RE-CLUSTERED (same Jaccard rule as D-029) with a new order: plateau_score first, rank_score second. `plateau_score` is the SMOOTHED mean = mean of the original result and of its finite ladder neighbours (+-1, +-2 quantile steps of one atom at a time, same feature and operator). A first version used the ratio median(neighbours)/original; it rewarded loose thresholds with a small original mean and put a worse rule first (the test `second_dedup_representative_is_the_best_plateau...` pins this). F2: >= 4 of 5 folds positive, >= 70% of usable periods positive (years; quarters when the train spans < 3 years; a period needs >= 10 episodes), no fold and no period holds > 50% of the profit, the 5 largest episodes <= 30% of the profit, leave-one-period-out positive in >= 80% of cases. F7: mean_gross - 1.5 x cost > 0 on the same rows (cost x 1.5 = spread, slippage, commission and swap). F4: median of neighbours >= 50% of the original, >= 80% of neighbours positive, a neighbour with < 30 observations is "no result"; an atom with no neighbours passes (NA). F6 is a SOFT Spearman score only (never rejects). Fingerprint sections: filters, candidates, discovery, atoms, features, labels, costs, data, plus the upstream fingerprint (`_downstream` helper, same pattern for stages 08 and 09).
- D-032 Stage numbering in the project is NOT the spec's. Project: 00 data_qa, 01 features, 02 labels, 03 eda, 04 atoms, 05 discovery, 06 candidates, 07 filters, 08 exits, 09 null, then 10 validation, 11 backtest, 12 ea. Every doc after this one uses the project numbers.
- D-033 Stage `08_exits` (M6, `discovery/exits.py`): the exit is chosen on a SMOOTHED surface of net R, never on the raw peak. Time stops: 3-point mean over the T ladder (1,2,3,6,12,24). Barriers: 3x3 mean over (tp, sl) within one horizon (12 or 24 separately). A cell is eligible with >= `candidates.min_episodes_train` episodes. A barrier replaces the best time stop only if it is better by `exits.min_improvement_R` (0.05 R) on the smoothed surface. Ties (rounded to 12 digits): time stop before barrier, interior cell before corner, shorter hold, then name. F3 = the chosen exit and its grid neighbours (up to 5 cells) have >= 3 positive and eligible cells. When a cluster has several members the representative is RE-PICKED among the members that pass F3 (so the frozen rule always has a robust exit). `frozen_ok` = F3 pass (config `exits.require_f3`). The decay gate of M8 must use `chosen_smooth`, not the raw peak.
- D-034 Stage `09_null` (M7, `nulltest/null.py`): the ONLY thing that changes between the real run and a replicate is a circular rotation of the label rows INSIDE THE TRAIN SEGMENT (offset in [embargo, n_train - embargo], embargo = max hold, so a rotated label cannot overlap its own trigger window). Features and atoms are untouched (they keep their autocorrelation and their calendar structure), labels keep their autocorrelation, and the whole search (coarse screen -> `build_candidates` -> `run_filters`) is repeated with the same config. S = max cluster t among rules that pass F1 and F2 (0 if none), S_cont = max exact cluster t of any survivor / family with enough episodes (a continuous statistic, since most null replicates have S = 0). p_global = (1 + #{S_null >= S_real}) / (R + 1). False-discovery estimate = mean(rules passing F1-F2 in the null) / (rules passing on the real data). G1 passes when: real data has rules, p_global_S <= 1 - quantile, false discovery < 0.5, replicates >= `min_replicates` (random variant). Variant `calendar`: offsets are multiples of the bars per calendar week (mode of the weekly bar counts), so hour-of-day and weekday alignment is preserved; a rule that beats the random null but not the calendar null is flagged `calendar_driven`. Replicates are stored one JSON per file with the fingerprint (search fingerprint, variant, rep, offset); a stopped run resumes (`--max-replicates`, `nulltest.max_seconds`), extending R reuses the first replicates (offsets are prefix-stable), a changed search invalidates everything.

- G-008 G1 compares p_global with `1 - quantile` using a 1e-9 tolerance: `1 - 0.9` is 0.09999999999999998 in floating point and would fail p = 0.1 exactly.
- D-037 Engine exit kinds (M9): `T{N}` time stop; `B{tp}_{sl}_{H}` bar boundary (decision on the closed bar, fill at the next open, exactly the label families; the reason `tp` / `sl` / `time` is read from the close of the last bar, which resolves D-015); `I{tp}_{sl}_{H}` intrabar RESEARCH mode: high / low touch a level, SL first when one bar touches both, a bar whose open is already beyond a level (bars after the entry bar only) fills at the open, otherwise at the level; the exit bar is the touching bar and the balance books it at the NEXT open. Short positions exit at the ask (price + spread of the exit bar), so a short TP / SL level is compared with high / low + spread. Intrabar exits have no MT5 equivalent in a bar-open tester; rules whose exit is `I...` are `research_only` and the code generator must refuse them (M10).
- D-038 Layers: the catastrophic stop (`cat_stop_atr`, wide intrabar SL) is searched only on bars STRICTLY before the exit decided so far (an exit at an open pre-empts the bar it happens in); the condition exit (decision on the closed bar b, fill at the open of b + 1) beats the base exit only if it comes strictly earlier, or ties with an intrabar touch (the open comes before the touch); a tie with an open-based exit goes to the base exit. Cat vs an intrabar SL inside one bar: the strategy SL wins (cat is expected to be wider).
- D-039 Positions: `max_open_positions` is per rule. A position frees the slot at the exit open (`reenter_on_exit_bar` true) or one bar later (false); with several positions the rule "no entry on a bar whose open closed ANY position" applies when `reenter_on_exit_bar` is false; an intrabar exit frees the slot for the next bar's entry in both modes. A signal with an invalid window does not block the next signal. `close_open_at_end` closes at the last bar open (reason `end`).
- D-040 Accounting: fill prices are the side prices of a tester list (long in at the ask, out at the bid; short in at the bid, out at the ask, slippage adverse on both fills). `r_net = profit / (lots x contract_size x ATR)` equals the label `net_R` for any sizing (tested). `risk_percent` floors to the lot step and clips to [lot_min, lot_max] (counted); the stop distance is `sl x ATR` or `cat_stop_atr x ATR`; without a stop it is an ERROR. Equity is marked at bar OPENS (long at the bid, short at the ask) and excludes accrued commission and swap (booked at the close). `cost_multiplier` multiplies spread and slippage only (design 15.5), not commission or swap (F7 in stage 7 multiplies all four; the two differ on purpose).
- D-041 Rule file: JSON, version 1, `{"rules": [ {rule_id, direction, atoms[{feature, op, threshold}], exit, cat_stop_atr, meta} ]}`, unknown fields are errors, atom semantics identical to `atoms.atoms` (tested against `AtomSet.dense`). Segment backtests restrict SIGNALS to the segment (exits may run past it; the embargo covers that) and compute drawdown / exposure on the segment window only. The holdout segment is refused by `run_backtest_stage` unless `allow_holdout=True` (reserved for the M8 validation stage).
- G-009 Not verifiable in the sandbox: a match against a real MT5 Strategy Tester trade list (G9). `mt5_backtest/compare.py` and the engine are ready; run `compare_trades` on a tester export from the user's MT5 once the EA exists (M10).
- D-042 Stage `10_validation` (M8, `validation/gates.py`): the frozen rules are the Stage 8 representatives with `frozen_ok`, best train `plateau_score` first, capped at `validation.max_rules` (train-only ranking). K of the Bonferroni correction = the number of rules actually tested. Critical t = Student-t `isf(alpha / K, df = n_trade_clusters - 1)` (inf with fewer than 2 clusters). Trade clusters = trades whose entry bars are at most one hold length apart (overlapping price paths); the mean and SE are `cluster_mean_se` on the engine's `r_net`. G5 decay compares validation mean R with the TRAIN SMOOTHED expectancy of the chosen exit, never the raw peak. G7 = engine rerun with `engine.cost_multiplier x validation.cost_stress_mult` (spread and slippage only, D-040): same trades, costlier fills. G4 is the only label-based gate: F5 on the validation rows with the Stage 6 estimator; the train side is read from Stage 6, and RECOMPUTED on the train rows when Stage 6 stored none (it stores the lift only for families that passed episodes and t; `lift_train_source` says which). Every threshold lives in the pure function `apply_gates` (NaN never passes; an infinite profit factor does). G9 / G11 are placeholders (`PENDING`), G10 is filled by the holdout step.
- D-043 Holdout protocol (`validation/holdout.py`, design 14.4): (1) a `start` record is written to `manifest.json` BEFORE any holdout row is read; (2) the engine runs on the holdout rows, each eligible rule alone; (3) `holdout_results.json` is created with mode `x` and made read-only; (4) a `complete` record is appended. A second opening is refused, also after a crash between (1) and (4) (state `started` = the holdout may have been seen = used). Refusals that happen before (1) (stale stage 10, nothing eligible, empty segment, duplicate ids) log nothing and burn nothing. Verdicts are bound to a hash of what the engine reads from the rule (`rule_sha`, never `meta`): a rule whose hash differs, or that was not opened, shows `BURNED`. Verdict: INCONCLUSIVE below `min_holdout_trades`; PASS = positive mean R and positive net profit; else FAIL. Stage 10 opens the holdout only when `validation.open_holdout` is true (default false) or via `scripts/open_holdout.py --yes-i-will-not-tune-after-this`. `run_backtest_stage` still refuses `segment="holdout"`.
- D-044 Outer walk-forward (`validation/walkforward.py`, design 14.3): the raw CSV is cut into windows; each window runs stages 0-8 as its own run folder with `train_pct` = train share of the window, `holdout_pct = 0` (D-044a: `make_splits` treats 0 as "no holdout", validation runs to the last row), so the test part is the "validation" segment of the mini run and is never read by stages 1-8. The best `max_rules_per_window` representatives are frozen and traded on the test part with ONE shared account per window. Rows after the FULL run's holdout start (minus the embargo) are never used, so the walk-forward does not read the holdout. Per-window null tests are not run; `require_null_approx` filters by the best-family t against the random-variant threshold of the full run's stage 9 and the report flags it as an approximation (the threshold value is part of the window fingerprint). Pooled OOS drawdown is built from `profit` in exit-time order (fixed lots assumed: with `risk_percent` compounding, profits of separate windows are not on one account).
- D-045 Stage 11 (`11_backtest`) backtests only the rules ACCEPTED by stage 10 (G2-G8) on train and validation, one shared account; the holdout is not part of it.

- D-047 EA algorithm (`render.TEMPLATE`, modelled in `ea_sim.simulate_ea`): act only on the first tick of a new bar. Order: (a) exit the open position, (b) feature dump (optional), (c) entry if flat and (`InpReenterOnExitBar` or no exit on this bar). Bars held = `iBarShift(position open time)` (the entry bar is shift `held`, the signal bar `held + 1`). `T{N}`: close when `held >= N`. `B{tp}_{sl}_{H}`: levels from the position open price and ATR(shift `held + 1`) recomputed from the indicator buffer (nothing is stored, so an EA restart loses nothing); `held >= 1`: close if `close[1]` is beyond a level, and always when `held >= H`. Catastrophic stop = server-side SL set from the ask / bid at the order. Entry needs a valid ATR (the engine skips such signals) and, when `InpMaxGapHours > 0`, no gap between the signal bar and the entry bar.
